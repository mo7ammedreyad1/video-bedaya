# هوية "تسلسل" (Sequence) — رندر ودمج عدة ملفات `scene.html`، أو استكمال فيديو موجود

**ملخص تنفيذي**: مش هوية بصرية، ومش منهجية ارتجال — **إجراء تنفيذي بحت**.
تُستخدم لما المستخدم بيبعت قايمة روابط مرتبة لأكتر من ملف `scene.html`
جاهز (كل واحد مكتوب مسبقًا، غالبًا عبر `ofoqagent.md`/`channel_v2.md`
بنظام الـ Sequences بتاعهم) وعاوز يرندرهم ويدمجهم في فيديو واحد نهائي —
أو يستكمل فيديو نهائي سابق بمشاهد جديدة بعده. مفيش أي قرار بصري هنا؛ القرارات
كلها اتاخدت مسبقًا جوه كل ملف على حدة.

## 1. الشرط
المستخدم بعت **قايمة روابط مباشرة مرتبة** (زي رابط GitHub Raw لكل ملف) —
ترتيب القايمة = ترتيب الفيديو النهائي — وسمّى هوية `sequence` صراحة، وطلب
رندرهم ودمجهم. اختياريًا، ممكن يبعت كمان رابط فيديو `.mp4` نهائي سابق
(دمجته أنت أو أي طريقة تانية قبل كده) عشان يتضاف المشاهد الجديدة بعده —
مش بدل منه.

## 2. المبدأ الجوهري: رندر منفصل لكل جزء، ثم دمج بـ ffmpeg
**ممنوع** محاولة دمج محتوى الملفات في كود `scene.html` واحد قبل الرندر —
ده هش ومعقّد بلا داعي. بدل كده: كل ملف يترندر لوحده بنفس `render-runner.js`
المرجعي في `AGENTS.md` قسم 5 **بدون أي تعديل فيه**، وبعدين الفيديوهات
الناتجة تتدمج بـ `ffmpeg` (نسخ تدفق مباشر، بدون إعادة ترميز).

## 3. الخطوات بالترتيب

### أ) تحميل الأجزاء بالترتيب
حمّل كل رابط بالترتيب المُعطى (`curl` أو أي أداة تحميل)، واحفظ كل ملف
باسم مرقّم يحفظ الترتيب: `part_01.html`, `part_02.html`, `part_03.html`...
لو المستخدم بعت رابط فيديو نهائي سابق (وضع الاستكمال)، حمّله باسم واضح
منفصل (زي `previous_final.mp4`) — ده هيتعامل معه لاحقًا كجزء جاهز، مش
`scene.html` يترندر.

### ب) تحقق العقد التقني لكل ملف
لكل `part_XX.html`، افتحه واتأكد إنه بيعرّف `CONFIG`، `OUTPUT_FILENAME`،
`audioBuffer`، `prepareIdentity()`، `drawSceneAtTime(time)` بنفس الأسماء
(زي `identities/build.md` بالظبط). **ممنوع تعديل أو "تصحيح" أي ملف من
عندك** — لو ملف ناقص العقد، أبلغ المستخدم بالضبط أي ملف وأي جزء ناقص،
واستنى توضيح بدل ما تفترض حل.

### جـ) رندر كل جزء لوحده
لكل `part_XX.html` بالترتيب:
1. انسخه ليكون `scene.html` (استبدال الملف اللي `render-runner.js` بيقرأه).
2. فحص headless سريع (قسم 2 بند 6 في `AGENTS.md`) — لو `SYNTAX_ERROR`، بلّغ
   المستخدم بأي جزء فشل بالتحديد وقف، ممنوع تكمل باقي الأجزاء.
3. شغّل `render-runner.js` المرجعي زي ما هو.
4. انقل الملف الناتج (`OUTPUT_FILENAME.mp4`) لاسم يحفظ الترتيب:
   `segment_01.mp4`, `segment_02.mp4`... إلخ.

### د) تحقق توافق إلزامي قبل الدمج
على **كل** الأجزاء (الفيديو النهائي السابق لو موجود + كل `segment_XX.mp4`
جديد)، شغّل:
```
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,r_frame_rate -of csv=p=0 <الملف>
```
قارن النتائج — لازم **كل** الأجزاء بنفس العرض والارتفاع والـ fps بالظبط.
**لو فيه ولو اختلاف واحد، قف فورًا وبلّغ المستخدم بالتفصيل (أي جزء مختلف
وبإيه) — ممنوع تحاول تدمج بالقوة**؛ الفشل بعد الدمج (فيديو متقطّع/مكسور)
أسوأ بكتير من التوقف الآن.

### هـ) الدمج
اكتب ملف قايمة نصي `filelist.txt` بمسارات كل الأجزاء بالترتيب الصحيح
(الفيديو السابق أولًا لو وضع استكمال، بعده الأجزاء الجديدة):
```
file 'previous_final.mp4'
file 'segment_01.mp4'
file 'segment_02.mp4'
```
وشغّل:
```
ffmpeg -y -f concat -safe 0 -i filelist.txt -c copy final_output.mp4
```
`-c copy` = نسخ تدفق مباشر بدون إعادة ترميز — سريع وآمن هنا لأن كل الأجزاء
أصلًا بنفس الكودك من نفس `render-runner.js` (أو نفس الكودك اللي الفيديو
السابق اتنتج بيه، بعد التحقق في الخطوة د).

### و) الرفع والتوثيق
ارفع `final_output.mp4` على GitHub Release زي أي فيديو عادي (`AGENTS.md`
قسم 5)، مع ملف وصف يوضح عدد الأجزاء المدموجة ومصادرها.

## 4. ملاحظات معروفة
- كل جزء بيحتفظ بصوته الخاص من داخل `scene.html` بتاعه — الدمج بياخد
  الصوت والصورة مع بعض تلقائيًا، مفيش تعامل منفصل مطلوب.
- لو عدد الأجزاء كبير وكل رندر بياخد وقت، إجمالي وقت التشغيلة ممكن يقرب
  من مهلة الـ job (90 دقيقة حاليًا) — لو توقعت العدد كبير جدًا، نبّه
  المستخدم بدري بدل ما تكتشف قرب نهاية المهلة.
- الملفات اللي بتيجي من `ofoqagent.md`/`channel_v2.md` بنظام الـ Sequences
  بتاعهم مصممة أصلًا بنفس الأبعاد/الـ fps لبعضها البعض — التحقق في الخطوة
  (د) غالبًا هينجح تلقائيًا لو كل الأجزاء من نفس المشروع، لكن يفضل إلزامي
  برضه (منع افتراض بدل تحقق فعلي).
